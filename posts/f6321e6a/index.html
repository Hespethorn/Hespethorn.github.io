一、主流 Linux 软件管理机制

目前主流 Linux 发行版使用的软件管理机制主要有两类：

发行版代表 软件管理机制 使用指令 线上升级机制 (指令)
Red Hat/Fedora RPM rpm, rpmbuild YUM (yum, dnf)
Debian/Ubuntu DPKG dpkg APT (apt-get)
RockyLinux RPM rpm, rpmbuild YUM (yum, dnf)

二、RPM 基础概念

2.1 RPM 简介

  • 全称：RedHat Package Manager
  • 特点：以数据库记录方式管理软件安装，安装前检查依赖关系
  • 优势：
    • 预编译打包，安装方便
    • 数据库记录软件信息，便于查询、升级和反安装
  • SRPM：含源代码的 RPM 包，用于自定义修改软件参数

2.2 RPM 软件命名规则

2.3 硬件平台标识

  • 常见标识：i686, x86_64, noarch
  • noarch：不依赖硬件架构的软件包

2.4 RPM 优点

  1. 包含预编译程序和配置文件，免除重新编译
  2. 安装前检查系统环境，避免错误安装
  3. 提供详细的软件信息
  4. 数据库管理便于升级、移除、查询与验证

2.5 依赖问题与解决

  • 依赖问题：上层软件依赖底层软件，未安装会导致安装失败
  • 解决方式：使用 YUM 在线升级机制，自动分析并解决依赖关系

  • U：文件所属人改变
  • G：文件所属群组改变
  • T：文件建立时间改变

五、Linux 日志管理简介

5.1 主要日志文件位置

  • 大多数日志位于 /var/log 目录
  • 常见日志文件：
    • /var/log/messages：系统错误和重要信息
    • /var/log/secure：认证相关信息
    • /var/log/cron：计划任务信息
    • /var/log/maillog：邮件系统信息

5.2 日志服务

  • rsyslog：系统和网络服务日志记录
  • systemd-journald：systemd 提供的日志服务，记录开机过程信息
  • logrotate：日志轮换，防止日志文件过大

5.3 日志查询命令

  • journalctl：查询 systemd-journald 日志
