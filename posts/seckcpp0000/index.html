秒杀系统高并发优化实战（C++ / Drogon）· 总路线图（Master Plan）

目标：用「讲透式」博客（是什么 → 坑在哪 → 本质一句话 → 关键 C++ 代码 / 内联 SVG → 对比表）从 0 到 1 用 C++ 渐进式搭建一个支撑高并发的秒杀系统。
通过问题驱动 + 压测验证，把系统 QPS 从 50 拉到 30000+，清晰看到「单体 → 微服务」的架构演进全过程。
这是作者个人的实战记录：重点不在堆功能，而是每一步的项目思考、实现路径，以及关键功能抉择上的权衡（例如"为什么 Redis 预热而不是直接落库""为什么 Lua 原子扣减而不是分布式锁""为什么异步下单而不是同步落库"），并补上 C++ 特有的系统级拆解（epoll、协程、无锁队列、内存池）。
读法：先骨架后血肉——先把「业务挑战 + 4 阶段架构演进」看明白，再逐阶段下钻到表设计、登录、缓存、MQ、Lua 预扣、防刷限流。

〇、阅读约定（本系列）

  • 技术栈（C++ 实现）：
    • Web 框架：Drogon（C++14/17，基于 epoll 的异步 I/O + 协程，内置 JSON / ORM / Redis 客户端）
    • 数据库：MySQL（mysql-connector-cpp 或 soci + 自管理连接池）
    • 缓存：Redis（redis-plus-plus 封装 hiredis；库存预热、Lua 原子脚本）
    • 消息队列：RabbitMQ（AMQP-CPP；阶段四内部 RPC 改用 brpc）
    • 鉴权/会话：自实现 Token（jwt-cpp + Redis 会话）
    • 分布式锁 / 限流：自实现（Redis SET NX + Lua；令牌桶 / 漏桶算法）
    • 注册配置（阶段四）：etcd 或自写轻量注册
    • 压测：JMeter（客户端语言无关）；容器：Docker
  • 每篇结构：开场钩子 → 「是什么 / 坑在哪 / 本质一句话」递进 → 贴出关键 C++ 代码（Drogon handler / SQL / Redis Lua / AMQP）→ 可运行步骤 → 内联 SVG 时序 / 架构图 → 对比表。
  • 每篇必带「功能抉择」小节：不只给方案，更给"为什么选 A 而不是 B、放弃了什么代价"的权衡（这是本系列区别于"功能清单式教程"的主线）。
  • 图一律 SVG（不写 ASCII 图）。

一、为什么要做秒杀系统（7 大业务挑战，语言无关）

秒杀是互联网大厂面试高频考点，也是最能体现高并发架构设计能力的实战项目。需逐个攻克：

  1. 瞬时高并发流量：活动开始请求量达平时几十~上百倍，连接 / 数据库被耗尽。
  2. 库存超卖：10000 人抢 100 件，如何不多卖。
  3. 重复下单：同一用户多次秒杀成功，如何防止。
  4. 黄牛刷单：脚本 / 机器人 / 多账号抢购，如何保公平。
  5. 服务雪崩：下游订单 / 支付慢导致调用方资源占满，级联故障。
  6. 数据一致性：Redis 预减 + MQ 异步下单 + DB 最终扣减，如何不丢不一致。
  7. 系统可扩展性：用户量 / 活动规模增长，如何水平扩展。

本系列视角：以上每个坑都当成一次功能抉择来讲——不只给"怎么解"，更给"为什么选它、为此放弃了什么"。例如超卖，乐观锁 / 悲观锁 / SQL 条件判断各有代价，要讲清取舍而非只甩一句"用乐观锁"。

五、你能学到什么（C++ 能力地图）

  • 从 0 到 1 用 C++ 把 QPS 从 50 拉到 30000+；
  • Drogon 全栈：异步 I/O、协程、REST 路由、内置 ORM / Redis 客户端；
  • MySQL 接入与连接池自管理（HikariCP 思路移植）；
  • Redis（redis-plus-plus）：库存预热、Lua 原子扣减、缓存穿透 / 击穿 / 雪崩三大解法；
  • 消息队列（AMQP-CPP）：异步下单、削峰填谷、Confirm/Return + 手动 ACK + 死信可靠性；
  • 分布式锁 / 限流自实现（Redis SET NX + Lua、令牌桶 / 漏桶）—— Java 生态开箱即用，这里全自己写，更见功力；
  • 系统级拆解：epoll 事件循环、协程切换开销、无锁环形队列、对象池 / 内存池、原子与内存序；
  • 页面静态化 + CDN、JWT 鉴权与会话；
  • 单体到微服务演进：brpc 内部 RPC、etcd 注册配置、自写网关与熔断；
  • Docker 中间件、JMeter 压测逐阶段验收、生产级库存 / 售罄 / 闸门方案。

六、适用人群与技术储备

  • 适用人群：有 C++ 基础、想做高并发 / 系统编程实战的开发者；系统岗 / 后端岗面试需要差异化项目加分。
  • 技术储备：现代 C++（C++14/17，懂智能指针 / 协程 / 原子更好）；用过 Drogon 或愿意学；了解 MySQL / Redis 基础。

七、关于本系列

  • 本系列是作者个人用 C++ 从零搭建高并发秒杀系统的实战记录，所有方案、代码、压测数据均为原创。
  • 写作主线不是"堆功能清单"，而是项目思考 + 实现路径 + 功能抉择的权衡：每个决策都交代"为什么选 A 而不是 B、放弃了什么代价"。
  • 若你更熟悉 Java 生态（Spring Boot / Redisson / Sentinel），可把文中的 C++ 自实现组件对照理解为对应中间件的等价物，但本系列不依赖任何外部教程。
