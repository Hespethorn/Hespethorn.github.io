## 个人介绍

我是周成昕，华中科技大学工学学士。长期在 Linux 环境下写 C++ 与后端系统，关注高性能服务、网络编程、缓存与存储。技术上有一种近乎固执的习惯：先读实现，再写最小复现，最后用数据把结论钉死——不接受“看起来对”。

在个人项目 **seckill-cpp** 中，用 C++ / Drogon 从零实现了一套高并发秒杀系统：从 MySQL 直连、原子扣减与幂等下单，到 Redis 缓存、布隆过滤器、本地 LRU 多级缓存与在途闸门；用 JMeter 记录每一步基线（直连 QPS≈440、缓存后 list 10557 / detail 8024、命中率 83.8%），并把路线图和每一次取舍写进仓库文档。这套系统真正训练的是判断力：什么时候该加缓存、加在哪一层、加完之后一致性由谁兜底。

在开源方面，读 Drogon `RealIpResolver` 源码时发现它只支持 IPv4，提 issue #2596 并完成 PR #2598（3 文件、+255/−36，测试 5→14），由项目作者合并。这段经历后来写成《给 Drogon 提第一个 PR》，重点复盘“读源码得出的结论”和“能进上游的 patch”之间的取证纪律。

除了业务系统，我更在意基础设施该怎么做得更稳。**ConfigGraph** 是我为这件事写的三层运行时配置管理系统：用 `$base` / `$ref` 把分散在多处、互相覆盖的配置编译成一张继承图，运行时靠原子替换完成热重载，消掉传统 reload 里“读到一半、新旧配置混用”的窗口；持久化刻意选择 RDB 风格快照而非 WAL，用可预测的重启加载耗时换取实现上的简单。这套实现跑通了 22 项基准测试，正在向轻量嵌入式平台（如 RK3588）上验证，并整理成中英双版本的论文与几项关联专利。

早期的工程经验留给我一个到现在还在追的问题：检索系统里，某些字段权重给得很足，召回来的内容却并不相关。当时以为是公式没调好，后来才想明白，问题常常不在权重本身，而在查询和文档压根不在同一个语域里。这份体感是现在做“查询语域感知的查询表示归一化”方向专利的起点，也让我对“权重调参”这类表面解法始终保持警惕。

写作是另一条主线。个人博客持续输出 800+ 篇技术文章，覆盖 CS 基础（CS50 / 61A / 61B / CSAPP / OS）、系统与工程、C++ / Linux / 网络 / 数据库，以及 AI 观察。这些不是零散笔记，而是按课程与主题成系列推进的：CS61A、CS61B 各 40 讲的完整拆解，Netty 4.1 源码 31 篇逐层往下读，秒杀系统的每一步演进单独成篇。写作对我最大的价值是把零散经验压成可复用的判断，同时逼自己把每个结论都跑一遍验证。

如果要用一句话概括我做事的方式：把“我觉得”换成“我测过”。结论能被别人复现，代码能被上游接受，才算真的懂。
