## 一、为什么 CS61A 从"函数"讲起

CS61A 全称 *Structure and Interpretation of Computer Programs*。它不先教语法，而是先教一件事：**计算过程如何管理"名字"与"值"的关系**。把这层吃透，后面的高阶函数、递归、面向对象都是顺理成章的延伸，而不是一堆零散语法。

## 二、调用表达式怎么求值

Python 里 `square(3 + 4)` 这种"操作符(操作数)"结构叫**调用表达式**。求值分两步，顺序很关键：

1. 先**从左到右**求值所有操作数（operand）：`3 + 4` 先算出 `7`；
2. 再把操作符（函数对象）作用于求值后的操作数。

```python
def square(x):
    return x * x

print(square(3 + 4))        # 先算 3+4=7，再 square(7)
print(square(square(2)))    # 内层 square(2)=4，再 square(4)=16
```

输出：

```
49
16
```

嵌套调用也是同样规则：从最内层开始，一层层把"值"算出来往外递。

## 三、环境：名字在哪里找值

**环境**（environment）是一张把名字映射到值的表。每次调用函数，解释器新建一个**局部帧（frame）**，函数里的形参 `x` 就在这个帧里绑定到实参。

查找顺序：先在**当前帧**找，找不到就沿**环境链**往上走到全局环境。

```python
x = 10              # 全局环境里的 x
def f(y):
    return x + y   # 函数体里找不到 x，沿链到全局拿到 10
print(f(5))        # 15
```

输出：

```
15
```

## 四、画一张环境图

环境图是 CS61A 的核心工具，能让你"看见"名字绑定：

```
全局环境
┌──────────────────────────┐
│ square ──> <function>    │
│ x ──> 10                 │
└──────────────────────────┘
        ▲ 调用 f(5) 时建立局部帧
        │
┌──────────────────────────┐
│ 局部帧 f: y = 5          │
│ return x + y = 15       │
└──────────────────────────┘
```

**关键认知**：函数体里的 `x` 指的是"调用时所在帧沿链能找到的 x"，不是写代码时的 x。这解释了为什么不同调用之间互不干扰——每次调用都有自己独立的帧。

## 五、名称、赋值与控制流

`=` 是**绑定**（把名字指向一个值），不是数学里的"等于"。它只改变名字指向哪，不改变值本身。

```python
a = [1, 2, 3]
b = a          # b 和 a 指向同一个列表（别名，见篇五）
b.append(4)
print(a)       # [1, 2, 3, 4]，因为改的是同一个对象
```

控制流决定执行路径：

- `if / elif / else`：按条件选一条分支；
- `while`：条件为真就重复；
- `for`：遍历序列每个元素。

```python
def abs_val(n):
    if n < 0:
        return -n
    return n

print(abs_val(-5), abs_val(3))
```

输出：

```
5 3
```

## 六、小结

- **调用表达式**：先算操作数，再调用操作符。
- **环境** = 名字→值的映射；每次函数调用开新帧，沿链查找。
- **`=` 是绑定不是等于**；控制流决定走哪条路。
