> CS61B 专栏第 1 篇。61B 用 Java 讲数据结构，但思想与语言无关。本篇先把「数据结构为什么存在」「抽象数据类型（ADT）是什么」讲透，并建立贯穿全季的观察视角：**数据结构 = 数据 + 在其上被允许的操作集合**。

## 1. 为什么需要数据结构

写程序本质上是在两件事之间反复横跳：

```
   真实世界的问题
        │  (建模)
        ▼
   计算机里的数据表示
        │  (算法操作)
        ▼
   被解决的问题
```

同样一组数字，你既可以把它们排成一排（数组），也可以串成一条链（链表），还可以塞进一棵树。选择不同，**同样的操作（查找、插入、删除）快慢天差地别**。数据结构研究的就是：用什么方式组织数据，能让目标操作又快又省。

> 61A 你已经学过「抽象」：把「怎么用」和「怎么实现」分开。61B 把这个思路推进到数据本身——这就是 **ADT**。

## 2. 抽象数据类型（ADT）到底是什么

**ADT = 一种数据类型的外在契约**：它规定了
1. 这个类型里**能存什么**数据；
2. 在它之上**能做什么操作**（以及每个操作的含义）；
3. **不规定**这些操作内部如何实现。

经典比喻：ADT 是「菜单 + 服务承诺」，具体实现是「后厨怎么炒菜」。客人（调用者）只关心端上来的菜对不对，不关心锅怎么颠。

用一个最简单的 `IntStack`（整数栈）ADT 举例：

```
┌─────────────────────────────────────────────┐
│  ADT IntStack                                │
├─────────────────────────────────────────────┤
│  数据: 一串整数（顺序未规定如何实现）        │
│  操作:                                        │
│    push(x)   —— 把 x 压到栈顶                │
│    pop()     —— 移除并返回栈顶元素           │
│    peek()    —— 看栈顶但不移除               │
│    isEmpty() —— 是否为空                     │
│  规约(不变量):                               │
│    pop 之前必 push；空栈 pop 报错            │
└─────────────────────────────────────────────┘
         │                    │
   实现 A: 数组         实现 B: 链表
   (连续内存)           (分散节点)
```

同一个 ADT，可以有两种（甚至更多）实现，对外行为一致，内部天差地别。这就是「抽象」的价值：**换实现不影响调用方一行代码**。

## 3. Java 里怎么把 ADT 落成代码

Java 用 `interface` 表达 ADT 的「契约」，用 `class` 表达具体实现。先写契约：

```java
// ADT 契约：只说能做什么，不说怎么做
public interface IntStack {
    void push(int x);     // 压栈
    int pop();            // 弹栈
    int peek();           // 看顶
    boolean isEmpty();    // 判空
}
```

再用**数组**实现（先不考虑扩容，聚焦思想）：

```java
public class ArrayIntStack implements IntStack {
    private int[] a = new int[10];  // 底层数组
    private int n = 0;              // 栈顶指针：指向下一个空位

    public void push(int x) {
        a[n] = x;
        n++;                        // 指针上移
    }
    public int pop() {
        n--;                        // 指针下移
        return a[n];                // 返回原栈顶
    }
    public int peek() {
        return a[n - 1];
    }
    public boolean isEmpty() {
        return n == 0;
    }
}
```

调用方只依赖 `IntStack` 接口：

```java
IntStack s = new ArrayIntStack();  // 想换实现只改这一行
s.push(1); s.push(2);
System.out.println(s.pop());       // 2
System.out.println(s.peek());      // 1
```

输出：
```
2
1
```

## 4. C++ 对照：同样的 ADT，另一种落地

C++ 没有 interface 关键字，用**纯虚类**表达契约；实现则用 `std::vector` 当底层数组（等价于 Java 的动态数组）：

```cpp
#include <vector>
#include <stdexcept>

class IntStack {            // 纯虚类 = ADT 契约
public:
    virtual ~IntStack() = default;
    virtual void push(int x) = 0;
    virtual int pop() = 0;
    virtual int peek() = 0;
    virtual bool empty() const = 0;
};

class VectorIntStack : public IntStack {
    std::vector<int> v;     // 底层动态数组
public:
    void push(int x) override { v.push_back(x); }
    int pop() override {
        if (v.empty()) throw std::runtime_error("empty");
        int x = v.back(); v.pop_back(); return x;
    }
    int peek() override { return v.back(); }
    bool empty() const override { return v.empty(); }
};
```

对照要点：

| 概念 | Java | C++ |
|------|------|-----|
| ADT 契约 | `interface` | 纯虚类（含 `=0` 的虚函数） |
| 实现绑定 | `implements` | `: public` + `override` |
| 动态数组 | `int[]` + 手写扩容 | `std::vector`（自带扩容） |
| 空栈处理 | 可抛异常/返回特殊值 | 抛 `std::runtime_error` |

**关键共识**：两种语言都把「契约」和「实现」分开。换实现（数组 ↔ 链表）时，调用方代码一字不改——这正是 ADT 设计的回报。

## 5. 本季贯穿的一条主线

从下一篇开始，我们会逐个落地具体数据结构。请始终带着三个问题读每一篇：

```
   Q1. 这个结构的 ADT 契约是什么？（能做什么）
   Q2. 它用什么方式在内存里组织数据？（数组/指针）
   Q3. 关键操作（查找/插入/删除）的时间复杂度是多少？
       为什么是这个量级？能不能更好？
```

```
   数组实现                 链表实现
   ┌──┬──┬──┬──┐           [3]→[7]→[1]→[9]→null
   │3 │7 │1 │9 │
   └──┴──┴──┴──┘
   连续内存, 随机访问 O(1)   分散节点, 访问靠遍历 O(n)
   插入/删除需搬移元素        插入/删除改指针即可
```

> 记住这句话：**没有「最好」的数据结构，只有「最适合当前操作 profile」的结构。** 后续所有篇章都是在拆解这个判断。

## 6. 小结

- 数据结构存在的意义：组织数据以优化目标操作的成本。
- ADT = 数据 + 允许的操作 + 规约；它只定契约，不定实现。
- Java 用 `interface`、C++ 用纯虚类表达 ADT；换实现不影响调用方。
- 评价一个结构，永远回到「时间复杂度」与「内存布局」两条轴。
