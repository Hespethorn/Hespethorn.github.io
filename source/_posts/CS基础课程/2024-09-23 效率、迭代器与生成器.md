## 一、增长阶（大 O）：看"规模翻倍时耗时怎么变"

衡量算法效率看**输入规模 n 增长时，步数怎么随 n 变化**，忽略常数。常见阶：

| 阶 | 含义 | 例子 |
|----|------|------|
| O(1) | 常数 | 列表下标访问 |
| O(n) | 线性 | 遍历一遍 |
| O(n²) | 平方 | 双层嵌套循环 |
| O(2ⁿ) | 指数 | 朴素斐波那契 |

## 二、为什么朴素 fib 那么慢

篇三的 `fib` 是 O(2ⁿ)：`fib(5)` 重复算 `fib(3)` 两次。n 每 +1，调用数约翻倍。n=40 就要上亿次调用。

**修法一：迭代**（O(n)）

```python
def fib_iter(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

**修法二：记忆化**（O(n)，用字典缓存）

```python
from functools import lru_cache
@lru_cache(maxsize=None)
def fib(n):
    if n < 2: return n
    return fib(n - 1) + fib(n - 2)
```

## 三、迭代器协议：for 循环背后是什么

任何能用 `for x in obj` 的对象都实现了**迭代器协议**：

- `__iter__()` 返回迭代器自身；
- `__next__()` 返回下一个元素，没了就抛 `StopIteration`。

```python
class CountUp:
    def __init__(self, n):
        self.n = n
        self.i = 0
    def __iter__(self):
        return self
    def __next__(self):
        if self.i >= self.n:
            raise StopIteration
        self.i += 1
        return self.i

print(list(CountUp(3)))      # [1, 2, 3]
```

输出：

```
[1, 2, 3]
```

## 四、生成器：用 yield 写迭代器

`yield` 让函数变成**生成器**——每次执行到 `yield` 就"暂停并返回"，下次从暂停处继续。比手写 `__next__` 简单得多。

```python
def gen_fib():
    a, b = 0, 1
    while True:
        yield a
        a, b = b, a + b

g = gen_fib()
for _ in range(8):
    print(next(g), end=" ")     # 0 1 1 2 3 5 8 13
```

输出：

```
0 1 1 2 3 5 8 13
```

## 五、惰性求值：不提前造全，要一个给一个

`range(10**9)` 不会真造十亿个数，它**惰性**地按需产生——这就是迭代器的价值：省内存、可表示无限序列（如上面的 `gen_fib`）。

**C++ 对照**：C++ 的"惰性序列"要写迭代器类或借助 `std::ranges`（C++20），远不如 Python 生成器随手。动态语言在"描述数据流"上就是省力。

## 六、小结

- 效率看**增长阶**；朴素递归 fib 是 O(2ⁿ)，迭代/记忆化降到 O(n)。
- **迭代器协议** = `__iter__` + `__next__`；`for` 循环靠它驱动。
- **生成器（yield）** 是写迭代器最省事的方式，天然支持**惰性求值**。
