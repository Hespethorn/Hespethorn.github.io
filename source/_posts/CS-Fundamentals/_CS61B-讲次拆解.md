# 第一模块：Java 语言基础与面向对象编程（Lecture 1–12）

## Lecture 1 · Intro, Hello World Java

**① 核心主题与目标**
建立 Java 的编译—运行心智模型：源码 → 字节码 → JVM 执行，并说清静态类型检查发生在什么时刻。

**② 主要知识点拆解**
- **两段式工具链**：`javac X.java` 产出 `X.class`（字节码），`java X` 才真正运行。
- **入口签名**：`public static void main(String[] args)`，三段修饰缺一不可。
- **静态类型**：变量声明时必须给出类型，类型错误在**编译期**就报，不等到运行。
- **基本类型 vs 引用类型**：`int`/`double`/`boolean` 直接存值；对象变量存的是引用。

**③ 典型应用/代码示例**
最小可运行程序 + 类型检查失败的两个对照版本。

**④ 易错点与难点**
- 文件名必须与 `public` 类名一致，否则 `javac` 直接拒绝。
- 忘记 `static` 时 `java` 报 "Main method is not static"。
- `/` 在整数之间是整除，与 Python 的 `/` 语义不同。

## Lecture 4 · References, Recursion, and Lists

**① 核心主题与目标**
把「引用」这一层语义彻底钉死，再用它造出第一个递归数据结构：裸链表 `IntList`。

**② 主要知识点拆解**
- **引用的本质**：变量里存的是指向对象的位串（Bits），不是对象本身。
- **Walrus 规则**：`b = a` 只复制指针，两个名字指向同一对象。
- **`null` 与 `NullPointerException`**：解引用 `null` 才抛，声明时不会抛。
- **递归改写循环**：`IntList` 的 `size` / `iterativeSize` 两版对照。
- **不可变递归数据**：`incrList` 返回新链，不修改原链。

**③ 典型应用/代码示例**
`IntList` 的迭代版与递归版，配合对象标识 `==` 与内容相等 `equals` 的区别。

**④ 易错点与难点**
- 把 `==` 当作值比较（对引用类型比的是地址）。
- 递归基写错导致 `NullPointerException`（应判 `this == null` 而非 `this.rest == null` 混用）。
- 误以为赋值会复制整个对象。

## Lecture 5 · SLLists, Nested Classes, Sentinel Nodes

**① 核心主题与目标**
从裸链表升级到「用户看不见 `IntList`」的封装型单链表 `SLList`，并引入哨兵节点消除边界分支。

**② 主要知识点拆解**
- **封装动机**：裸链表要求调用方自己持有头引用，`SLList` 把 `IntNode` 藏进内部。
- **静态嵌套类**：`IntNode` 用 `static` 声明，它不持有外部实例的隐式引用。
- **哨兵节点（Sentinel）**：`sentinel.next` 恒为真实首节点，把「空表」和「非空」统一。
- **`size` 缓存**：用 `int size` 把 O(N) 的 `size()` 降到 O(1)。
- **退化情形**：无哨兵版 `addLast` 需要单独处理空表。

**③ 典型应用/代码示例**
`SLList` 的 `addFirst` / `addLast` / `get`，以及哨兵版与无哨兵版的对照。

**④ 易错点与难点**
- 静态嵌套类不能访问外部类的实例成员（`SLList.this`）。
- 有哨兵时 `getFirst` 应返回 `sentinel.next.item`，不要写成 `sentinel.item`。
- 空表下 `removeLast` 的 `prev.next == sentinel` 终止条件容易写错。

## Lecture 7 · ALists, Resizing, vs. SLLists

**① 核心主题与目标**
用数组实现动态列表 `AList`，把「扩容策略」与「均摊复杂度」讲透。

**② 主要知识点拆解**
- **数组作为底层存储**：`int[] items` + `int size`，`size` 不一定等于 `items.length`。
- **倍增扩容**：满了把容量乘 2，而不是加常数。
- **均摊分析（Amortized Analysis）**：从空数组连续 N 次 `addLast`，总搬运次数 ≈ 2N。
- **删除与缩容**：`removeLast` 后用 `size` 屏蔽尾部，必要时缩容。
- **选型对比**：`SLList` 头插 O(1)、按下标取 O(N)；`AList` 恰好相反。

**③ 典型应用/代码示例**
`AList.addLast` 的扩容实现 + 计数扩容次数的实测（N = 1,000,000 → 扩容 20 次）。

**④ 易错点与难点**
- 扩容写成 `size + 1` 或 `size * 2 - 1` 之类，退化成 O(N²)。
- 『数组长度』与『逻辑长度』混用。
- 误以为 `ArrayList` 的 `get` 是 O(1) 就说明所有操作都快。

## Lecture 10 · Subtype Polymorphism vs. HoFs

**① 核心主题与目标**
说清「子类型多态」与「高阶函数」是同一个问题的两种解法，并给出 Java 侧的动态绑定规则。

**② 主要知识点拆解**
- **静态类型 vs 动态类型**：编译期看声明类型，运行期按实际类型选方法。
- **接口（Interface）**：只声明签名，不写实现，充当「能力契约」。
- **动态绑定**：`Object` 数组里放不同实现，循环调用同一方法自动分派。
- **`Comparable` / `Comparator`**：Java 把「比较」抽象成接口，等价于高阶函数里的 `f`。
- **显式强转**：声明类型里没有的方法，必须先 `(RealType) x` 才能调用。

**③ 典型应用/代码示例**
`Comparator<T>` 版 `max` 与 `Comparable` 版 `max` 的对照实现。

**④ 易错点与难点**
- 调用声明类型不存在但实际类型存在的方法 → 编译失败，必须强转。
- `Comparator` 返回 `int`，写成 `boolean` 直接编译不过。
- 混淆「重载（overload，编译期定）」与「重写（override，运行期定）」。

# 第二模块：渐进分析基础与抽象数据类型（Lecture 13–16）

## Lecture 13 & 15 · Asymptotics I & II

**① 核心主题与目标**
建立渐进分析的完整记号体系，并会用递归关系推导复杂度。

**② 主要知识点拆解**
- **三个记号**：`O` 是上界、`Ω` 是下界、`Θ` 是紧确界；「大 O＝最坏情况」是错的。
- **化简规则**：丢弃常数因子与低阶项。
- **常见阶**：`1 < log N < N < N log N < N² < 2^N`。
- **递归关系**：`T(N) = 2T(N/2) + N` → `Θ(N log N)`。
- **空间复杂度**：`AList` 扩容峰值内存、递归调用栈深度。

**③ 典型应用/代码示例**
同一算法的循环版与递归版计数对照，实测调用次数。

**④ 易错点与难点**
- 把 `O(2N)` 与 `O(N)` 当两回事。
- 忽略循环体内隐藏的迭代成本（如字符串拼接、`substring`）。
- 用 `O(N²)` 的字符串拼接写循环。

## Lecture 14 · Disjoint Sets

**① 核心主题与目标**
掌握并查集的三代演化：Quick-Find → Quick-Union → 加权 Quick-Union + 路径压缩。

**② 主要知识点拆解**
- **ADT 定义**：`connect(a, b)` 与 `isConnected(a, b)`。
- **Quick-Find**：`id[]` 直接存根号，查找 O(1)、合并 O(N)。
- **Quick-Union**：`parent[]` 指向父节点，合并 O(1)、查找 O(树高)。
- **按大小加权**：小树挂到大树，树高降到 `O(log N)`。
- **路径压缩**：查找时顺手把节点挂到根，均摊接近阿克曼反函数 `α(N) ≈ 1`。

**③ 典型应用/代码示例**
三代实现同跑一组 `connect` 序列，打印 `parent[]` 观察树形演化。

**④ 易错点与难点**
- 判断连通时直接比较 `parent`，忘了递归 `find()` 找根。
- 加权时比较的是「树的大小（节点数）」，不是「树高」。
- 路径压缩写成只压一层。

## Lecture 16 · ADTs, Sets, Maps, BSTs

**① 核心主题与目标**
区分「抽象数据类型」与「数据结构实现」，并引入有序集合与二叉搜索树。

**② 主要知识点拆解**
- **ADT vs 实现**：`Set` / `Map` 是契约，`BST` / 哈希表是两种实现。
- **BST 有序性质**：左子树全部小于根、右子树全部大于根。
- **查找/插入**：沿单一路径下行，比较次数等于树高。
- **退化风险**：有序插入 → 退化成链表，操作从 `O(log N)` 掉到 `O(N)`。
- **遍历**：中序遍历得到升序序列，是 BST 的「指纹」。

**③ 典型应用/代码示例**
BST 的 `contains` / `insert` / `inOrder`，并实测有序插入导致的树高退化。

**④ 易错点与难点**
- 用 `left.right > node` 这类错误判据（BST 的约束是整棵子树，不是相邻节点）。
- 忘记处理重复值策略（允许 / 拒绝 / 记数）。
- 认为 `contains` 只比较相邻两层。

# 第三模块：平衡树、哈希表与优先队列（Lecture 17–20）

## Lecture 17 & 18 · B-Trees & Red-Black Trees

**① 核心主题与目标**
从「为什么 BST 会退化」出发，用 2-3 树解决平衡问题，再用左倾红黑树把它落到二叉树上。

**② 主要知识点拆解**
- **B 树 / 2-3 树**：节点可容纳多个键，插入溢出时分裂并向上传递。
- **完美平衡**：所有叶子在同一层，树高 `Θ(log N)`。
- **红黑树等价**：红边表示 2-3 树中的 3-节点，黑边是普通父子关系。
- **三个操作**：`rotateLeft`、`rotateRight`、`flipColors`。
- **不变式**：不允许红色右倾边、不允许连续两条红边、根节点恒为黑。

**③ 典型应用/代码示例**
从 2-3 树插入序列手工推演，再用 LLRB 的插入路径打印旋转/变色步骤。

**④ 易错点与难点**
- 旋转时指针更新顺序写反（先断后连的原则）。
- 无法把颜色变更与 2-3 树的分裂对应起来。
- 忘记最后把根强制置黑。

## Lecture 19 · Hashing

**① 核心主题与目标**
用哈希把「查找」从 `O(log N)` 降到均摊 `O(1)`，并说清 `hashCode`/`equals` 的契约。

**② 主要知识点拆解**
- **哈希函数**：把任意对象映射到 `int`，再对桶数取模。
- **冲突解决**：拉链法（每个桶挂链表/红黑树）与开放寻址（线性/二次探测）。
- **`equals` 与 `hashCode` 契约**：重写其一必须重写另一个。
- **装载因子**：元素数 / 桶数超过阈值触发扩容 + 重哈希。
- **可变对象的坑**：用可变对象当键且事后修改，会永远查不到。

**③ 典型应用/代码示例**
手写链地址法 `HashMap`（`put` / `get`），并实测不同哈希质量下的桶长分布。

**④ 易错点与难点**
- 只重写 `equals` 不重写 `hashCode` → 两个相等对象落到不同桶。
- 用可变对象做键。
- 把装载因子调得过高导致大量冲突、过低浪费内存。

## Lecture 20 · Heaps and PQs

**① 核心主题与目标**
用完全二叉树实现优先队列，把「堆序性」与「数组表示」讲透。

**② 主要知识点拆解**
- **PQ 是 ADT**：只要支持 `add` / `getSmallest` / `removeSmallest`。
- **最小堆性质**：父节点 ≤ 两个子节点；**不要求**左右子树有序。
- **数组表示**：节点 `k` 的左右子为 `2k` 与 `2k+1`（1-based）。
- **`swim` / `sink`**：插入上浮、删除根时把末尾元素换到根再下沉。
- **复杂度**：插入 `O(log N)`、取最小 `O(1)`、删除最小 `O(log N)`。

**③ 典型应用/代码示例**
数组版 `MinHeap`，打印内部数组验证堆序性。

**④ 易错点与难点**
- 把二叉堆与二叉搜索树混淆（堆无序！）。
- 直接遍历堆数组当有序输出。
- 下标从 0 开始时的子节点公式写成 `2k`（应为 `2k+1` / `2k+2`）。

# 第四模块：图算法、多维检索与前缀树（Lecture 21–26）

## Lecture 21 & 22 · Tree and Graph Traversals & Implementations

**① 核心主题与目标**
建立图的两种表示法，并用 DFS / BFS 解决连通性与最短跳数问题。

**② 主要知识点拆解**
- **图的表示**：邻接矩阵（`O(V²)` 空间）与邻接表（`O(V+E)` 空间）。
- **DFS**：借助栈/递归深入，天然产出拓扑序、连通分量。
- **BFS**：借助队列逐层扩展，在**无权图**上给出最短路径。
- **`marked[]` 不可省**：否则环上无限递归。
- **路径记录**：`edgeTo[]` 回溯出一条具体路径。

**③ 典型应用/代码示例**
邻接表图的 BFS 求最短跳数 + `edgeTo` 回溯路径。

**④ 易错点与难点**
- 忘记 `marked` 导致死循环 / 栈溢出。
- 用 BFS 求带权图最短路（应该用 Dijkstra）。
- 入队时就标 `marked` 还是出队时标，影响正确性。

## Lecture 23 · Shortest Paths (Dijkstra)

**① 核心主题与目标**
解决非负权单源最短路，吃透「松弛」这一核心动作。

**② 主要知识点拆解**
- **`distTo[]` 与 `edgeTo[]`**：前者记已知最短距离，后者记来路。
- **松弛（Relaxation）**：若 `distTo[v] + w < distTo[w]`，则更新 `distTo[w]`。
- **贪心选择**：每次从未确定节点里取 `distTo` 最小者「定型」。
- **优先队列加速**：`O(E log V)`。
- **负权失效**：已定型节点可能被更短路径推翻，Dijkstra 假设不成立。

**③ 典型应用/代码示例**
用 `PriorityQueue` 实现 Dijkstra，打印每轮定型的节点与 `distTo` 快照。

**④ 易错点与难点**
- 负权边仍用 Dijkstra。
- 忘记在松弛后更新 PQ 中的优先级。
- 把 `INF` 写成 `Integer.MAX_VALUE` 后直接相加溢出。

## Lecture 24 · Minimum Spanning Trees (Prim & Kruskal)

**① 核心主题与目标**
用两种贪心策略求最小生成树，并用切分定理统一解释二者为何正确。

**② 主要知识点拆解**
- **切分定理（Cut Property）**：横跨任意切分的最小权边必在 MST 中。
- **Prim**：从单点生长，每次取连接「树内—树外」的最小边。
- **Kruskal**：把全部边升序排列，用并查集跳过成环的边。
- **复杂度**：Prim 用 PQ 为 `O(E log V)`；Kruskal 为 `O(E log E)`。
- **负权与不连通**：MST 允许负权；不连通图只有最小生成森林。

**③ 典型应用/代码示例**
同一张图上跑 Prim 与 Kruskal，打印选中的边集并校验总权重一致。

**④ 易错点与难点**
- 把 Prim 当作 Dijkstra（Prim 只看当前边权，Dijkstra 看累积距离）。
- Kruskal 忘记用并查集判环。
- 认为 MST 唯一（权重相同时可能不唯一）。

## Lecture 26 · Prefix Operations and Tries

**① 核心主题与目标**
用前缀树把「按前缀检索」做到与词表规模无关。

**② 主要知识点拆解**
- **Trie 结构**：字符沿边存，节点代表一个前缀。
- **复杂度**：查找/插入只与字符串长度 L 有关，`O(L)`，与 N 无关。
- **`Map` 版节点**：字符集大时用 `Map<Character, Node>` 替代定长数组。
- **前缀计数**：节点上缓存 `size` 可支持「有多少词以此前缀开头」。
- **自动补全**：先走到前缀节点，再 DFS 收集所有后继词。

**③ 典型应用/代码示例**
`Map` 版 Trie 的 `add` / `contains` / `keysWithPrefix`。

**④ 易错点与难点**
- Unicode 场景下用定长数组导致内存爆炸。
- 忘记标记词尾（区分「是前缀」与「是完整词」）。
- 把 Trie 的 `O(L)` 误说成 `O(1)`。

# 第五模块：排序算法、工程实践与复杂度下界（Lecture 27–37）

## Lecture 29 · Basic Sorts

**① 核心主题与目标**
掌握三种基础排序的机制、稳定性与适用场景。

**② 主要知识点拆解**
- **选择排序**：每轮选最小放到前端，`Θ(N²)`，**不稳定**。
- **插入排序**：把当前元素插到已排序前缀的正确位置，近乎有序时接近 `O(N)`。
- **归并排序**：分治 + 合并，稳定且稳定 `O(N log N)`，代价是 `O(N)` 额外空间。
- **稳定性定义**：相等元素的相对次序是否被保留。
- **原地性**：选择/插入原地；归并需要辅助数组。

**③ 典型应用/代码示例**
三种排序作用于同一数组，打印每轮中间的数组状态。

**④ 易错点与难点**
- 误认为选择排序稳定。
- 归并的 `merge` 边界写成 `<=` 或 `<` 导致稳定性丢失。
- 把「插入排序最好情况 O(N)」误用到随机数据上。

## Lecture 30 & 32 · Quick Sort

**① 核心主题与目标**
掌握原地分治排序，并理解枢轴选择与重复元素带来的性能陷阱。

**② 主要知识点拆解**
- **分区（Partition）**：`O(N)` 把数组按枢轴分成两半。
- **平均复杂度**：`O(N log N)`，原地，无需额外数组。
- **最坏情况**：已排序数组 + 固定取端点枢轴 → `O(N²)`。
- **随机化枢轴 / 三数取中**：把最坏情况概率压到可忽略。
- **三路切分**：大量重复元素时分成 `<` / `=` / `>` 三段，避免退化为 `O(N²)`。

**③ 典型应用/代码示例**
三路切分快排 + 实测「全相等数组」下与双路快排的递归深度对比。

**④ 易错点与难点**
- 分区指针越界或死循环。
- 大量重复元素仍用双路切分。
- 认为快排「稳定」（它不稳定）。

## Lecture 34 · Sorting and Algorithmic Bounds

**① 核心主题与目标**
用决策树证明：任何基于比较的排序在最坏情况下都逃不出 `Ω(N log N)`。

**② 主要知识点拆解**
- **决策树模型**：每个内部节点是一次比较，叶子是一种排列。
- **叶子下界**：N 个元素有 `N!` 种排列，故叶子数 ≥ `N!`。
- **树高下界**：二叉树高度 ≥ `log₂(N!)`，由 Stirling 近似得 `≈ N log₂ N`。
- **结论边界**：只约束「基于比较」的算法。
- **突破方式**：利用键的结构（基数排序、计数排序）跳出比较模型。

**③ 典型应用/代码示例**
打印 `log₂(N!)` 与 `N log₂ N` 的数值对照，直观看到渐近吻合。

**④ 易错点与难点**
- 把下界误推广到所有排序（含非比较排序）。
- 混淆「下界」与「最优算法的复杂度」。
- 忘记 `N log₂ N` 中的常数来自 `log₂ N!` 展开。

## Lecture 35 · Radix Sorts

**① 核心主题与目标**
用「按位分桶」跳出比较模型，把字符串排序做到与 N 近似线性。

**② 主要知识点拆解**
- **计数排序（Counting Sort）**：键范围有限时 `O(N + R)`。
- **LSD 基数排序**：从最低位开始，逐位稳定排序。
- **MSD 基数排序**：从最高位开始，递归分治。
- **复杂度**：键长 W、字母表 R 时为 `O(W(N + R))`。
- **稳定性的硬要求**：LSD 每一位的排序必须是稳定的。

**③ 典型应用/代码示例**
LSD 基数排序处理定长字符串，逐轮打印分桶结果。

**④ 易错点与难点**
- 用不稳定排序做子过程，破坏低位已排好的顺序。
- 键长不一致时直接用 LSD（需先补齐或按长度分桶）。
- 认为基数排序适用所有场景（键很短、R 很大时不划算）。

# 第六模块：数据压缩与计算复杂性（Lecture 38–40）

## Lecture 38 & 39 · Compression & Complexity (P vs NP)

**① 核心主题与目标**
用前缀码把压缩做到最优，再进入计算复杂性：P、NP、NP-Complete 与规约。

**② 主要知识点拆解**
- **前缀码**：任一编码都不是另一编码的前缀 → 可无歧义解码。
- **霍夫曼编码**：反复合并频率最低的两个节点，自底向上建树。
- **最优性**：在给定符号频率与逐字符编码下，霍夫曼编码的加权码长最小。
- **P / NP**：P 可在多项式时间求解；NP 可在多项式时间验证。
- **规约与 NP-Complete**：任意 NP 问题都能多项式规约到 X，则 X 是 NP-Complete。
- **术语纠偏**：NP = Non-deterministic Polynomial，不是 Non-Polynomial。

**③ 典型应用/代码示例**
用 `PriorityQueue` 建霍夫曼树，输出每个字符的码字与加权码长。

**④ 易错点与难点**
- 混淆「多项式时间可验证」与「多项式时间可求解」。
- 认为 NP 表示「算不出来」。
- 忘记霍夫曼编码是最优**前缀码**，不是全局最优压缩。
