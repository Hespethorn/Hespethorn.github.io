## 二、模块拆分（8 个 Phase / 约 28 篇）

### Phase 0 · 准备与环境
1. 拉取源码、IDE 导入、跑通 `echo` 例子；本系列读法与本机环境约定

### Phase 1 · 宏观架构与启动流程（先看骨架）
2. Netty 整体架构：Reactor 模型 + 核心组件全景（Bootstrap / EventLoopGroup / Channel / Pipeline / Handler）
3. 服务端启动全流程：`ServerBootstrap` 配置 → `bind()` → `initAndRegister` → 注册到 EventLoop
4. 客户端启动与连接建立：`Bootstrap.connect()` 链路

### Phase 2 · NIO 基石与 Channel 抽象
5. Java NIO 回顾：Selector / Channel / Buffer，以及原生坑（epoll 空轮询、JDK NIO bug）
6. `Channel` 接口体系与 `ChannelPromise`（异步结果为什么这样设计）
7. `Unsafe` 内部类：真正的 I/O 操作为什么藏在 `Unsafe` 里
8. `NioServerSocketChannel` / `NioSocketChannel` 的创建与注册

### Phase 3 · 事件循环与线程模型（心脏）
9. `EventLoop` 与 `EventLoopGroup`：`SingleThreadEventExecutor` 源码
10. 任务队列与定时任务：`taskQueue` / `schedule` / `wakeup`
11. Reactor 线程 `run()` 主循环：`select` → `processSelectedKeys` → `runAllTasks`
12. 多线程模型：Boss/Worker 分组、Channel 如何绑定到固定 EventLoop（线程亲和）

### Phase 4 · ChannelPipeline 与事件传播（神经系统）
13. `ChannelPipeline` 双向链表结构与 `ChannelHandlerContext`
14. 入站 / 出站事件传播：`fireXXX` 与 `invokeXXX` 的双向流动
15. `HeadContext` / `TailContext` 的角色与收尾
16. 自定义 Handler 编排与异常传播（`exceptionCaught`）

### Phase 5 · 内存与 ByteBuf（血液）
17. `ByteBuf` 设计：读写指针分离、`ReferenceCounted` 引用计数
18. 内存分配：`ByteBufAllocator`、`Unpooled` vs `Pooled`
19. `PooledByteBufAllocator` 与 jemalloc 风格池化：`PoolArena` / `Chunk` / `Page` / `Subpage`
20. Netty 零拷贝：`CompositeByteBuf`、`slice`、`FileRegion`、`wrap`

### Phase 6 · 编解码与数据处理
21. Codec 框架：`ByteToMessageDecoder` / `MessageToByteEncoder`
22. 拆包 / 粘包：`LengthFieldBasedFrameDecoder` 源码走读
23. 常用编解码器：`String` / `Protobuf` / `HTTP`

### Phase 7 · 读 / 写 / 连接主链路串讲（收口）
24. 服务端读链路：`OP_ACCEPT` → 建连 → `OP_READ` → 数据流入 Pipeline
25. 写链路：`write` → `flush` → 真正 socket 写出 → `OP_WRITE` 可写性控制
26. 背压与可写性：`isWritable()` / `writabilityChanged`

### Phase 8 · 进阶主题（按需）
27. `Future` / `Promise` 异步模型与 `notify` 机制
28. 性能内核：`FastThreadLocal`、`Recycler` 对象池
29. 原生 `epoll` / `kqueue` 传输（Linux / macOS 优化）
30. 心跳与空闲检测：`IdleStateHandler`
31. 收尾：手写一个 mini-Netty（把核心机制复述一遍）
