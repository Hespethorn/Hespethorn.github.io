6.1 把 RabbitMQ 用 Docker 立起来了：交换机 `seckill.order.direct`、队列 `seckill.order.create`、路由键、`/seckill` vhost 全部写进了 `definitions.json`，容器重建后拓扑自动恢复。中间件这一侧已经定死。

现在轮到业务这一侧：**一个跑在 Drogon 上的 C++ 进程，怎么跟这台 Broker 说话？**

Java 生态里这不是个问题——`spring-boot-starter-amqp` 加一行依赖，@RabbitListener 加一个注解，收发就通了。C++ 没有这种东西。你得自己选客户端库、自己决定事件循环归谁管、自己处理"HTTP 线程里的请求怎么安全地把消息交给 Broker"这个跨线程问题。本篇就是把这个链路从零接通，并把每个取舍的原因写清楚。

> 本文是「秒杀系统（C++ / Drogon）」系列第六章第二篇。配套资产（本文新增，随 `v0.3.x` 落地）：`scripts/install-amqpcpp.sh`、`src/mq/MqEventLoop.{h,cc}`、`src/mq/MqClient.{h,cc}`、`tools/mq_smoke.cc`、`scripts/mq-check.sh`。仓库当前最新 tag `v1.0.0`（阶段二），**阶段三代码尚未入库**，故本文所有文件均以"本文新增"标注，文中 API 均为 AMQP-CPP 官方公开接口。真实环境：WSL Ubuntu（i7-14650HX）+ RabbitMQ 3.13-management-alpine。

## 一、AMQP-CPP 是什么、坑在哪、本质一句话

- **是什么**：AMQP-CPP 是一个**全异步、非阻塞**的 AMQP 0-9-1 协议库。它最反直觉的一点是——**它自己不做任何 IO**。不建 socket、不 read、不 write。它只负责"把一堆字节解析成帧"和"把操作编码成一堆字节"，真正的网络读写必须由你（宿主程序）完成，通过你实现的 `ConnectionHandler` / `TcpHandler` 接口回调给你。
- **坑（按踩到的概率排序）**：
  1. **编译不带 `-DAMQP-CPP_LINUX_TCP=ON`，就没有 TCP 模块**。`AMQP::TcpConnection` / `TcpChannel` / `linux_tcp.h` 全部不存在，报一堆"未定义的引用"。这是第一次接入的人 100% 会撞的墙，因为默认 `OFF`。
  2. **`AMQP::TcpConnection` 不是线程安全的**。所有对它的调用必须发生在**同一个线程**（驱动它的那个事件循环线程）。从 Drogon 的 HTTP IO 线程直接 `channel->publish()` 是数据竞争——不是"可能有风险"，是一定会出错，因为库内部会通过 `monitor()` 回调改写 fd 注册表。
  3. **`monitor()` 的 flags 可能为 0**，含义是"这个 fd 现在可读可写都不关心了"。没处理的话你的 epoll 会 level-trigger 疯狂唤醒，CPU 打满。
  4. **所有对象必须在 loop 线程析构**。`TcpConnection` 析构时会发 `connection.close` 帧，跨线程析构等于让另一个线程去操作一个已被释放的 socket。
- **本质一句话**：**AMQP-CPP 把"协议"和"网络"彻底分开卖，你要拿到它的全部价值，就必须先回答一个问题——谁的事件循环来驱动它。**

这个问题答不好，后面每一步都会变成灾难。所以它是本篇的第二个功能抉择。

## 二、功能抉择（一）：客户端库选型

C++ 里能连 RabbitMQ 的路就那么几条，把它们的代价摊开来：

| 方案 | 模型 | 选它的理由 | 放弃的代价 |
| --- | --- | --- | --- |
| **AMQP-CPP（选）** | 全异步、零 IO | 库不做 IO，因此**能塞进我自己的 epoll 循环**；publish/consume 全程无阻塞调用，与 Drogon 的 IO 线程模型天然合拍 | 文档薄，示例少；要自己实现 Handler，前期成本高；心智负担明显大于同类库 |
| SimpleAmqpClient | 同步阻塞 | API 最接近 Java 的 `BasicPublish`，上手 10 分钟 | **同步模型致命**：每 publish 一次就阻塞当前线程。放在 Drogon IO 线程会拖垮整个 HTTP 服务，放在线程池则额外背上线程切换成本。秒杀下单是一条超高并发路径，同步 IO 不可接受 |
| rabbitmq-c + 自写封装 | C API，半异步 | 事实标准 C 库，稳定；AMQP-CPP 之外的第二选择 | API 是 C 风格，要自己管连接状态机、帧缓冲、错误恢复；写薄之后基本等于重写一遍 AMQP-CPP 的 TCP 模块 |
| 手写 AMQP 帧编解码 | 完全自控 | 零依赖，极致可控 | 协议 = 帧格式 + 心跳 + channel 多路复用 + 握手，写完二千行起且没有保障。明确的过度设计 |

**决策**：选 AMQP-CPP。理由是它的设计哲学（"我不做 IO，你给我事件循环"）恰好是我们要的东西——我们本来就要在 C++ 侧严格掌控线程和 fd，一个**不抢控制权**的库比一个"帮你都包好"的库更符合这个项目。

**放弃的代价**明说：接受自己写 Handler（下文 80 行代码）和远不如 Java 的开发体验。这是一次性成本，付完就结束了。

## 三、功能抉择（二）：谁的事件循环——本篇的关键决策

选了 AMQP-CPP，它还欠我们一个驱动器。三条路：

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 再装一个 libevent / libuv | `AMQP::LibEventHandler` 官方现成 | 零代码 | **多一套事件循环依赖**。同一进程里跑 epoll（trantor）+ libevent 两套 loop，运维、排查、内存模型都要理解两遍。且仍然要解决跨线程投递 |
| 挂进 Drogon 的 trantor EventLoop | Handler 里持 `trantor::Channel` | 复用现有 loop，`runInLoop` 天然可用 | **耦合过深**：MQ 的慢事件会挤占 HTTP 的服务能力；且 trantor Channel 对 fd 变更（AMQP 重连后 fd 会换）的重建语义写起来并不省事 |
| **自建 MQ IO 线程 + 原生 epoll（选）** | 一个线程、一个 `epoll_fd`、一个 `eventfd` | 隔离干净（MQ 抖动不拖垮 HTTP）；fd 管理完全自控；`eventfd` 做跨线程投递是 Linux 上最轻的方案 | 要自己写约 150 行事件循环代码 |

**决策**：自建。**核心理由是隔离性**——秒杀场景下 MQ Broker 抖动、网络重连、慢消费都可能发生，绝不能让这些把 HTTP 服务能力拖下去。多一个线程、多一个 epoll 实例，换来清晰的故障边界，这笔交易划算。

**放弃的代价**明说：进程里多一个线程和一个 epoll 实例（约几十 KB），以及事件循环代码由自己维护。相较于"MQ 出问题导致整站 502"，这个代价可以忽略。

## 四、先把库装上：CMake 接入

那个 `ON` 开关就是坑一号，写进脚本一次解决：

```bash
# scripts/install-amqpcpp.sh（本文新增）
set -e
VER=v4.3.20
rm -rf /tmp/amqp-cpp
git clone --depth 1 --branch "$VER" https://github.com/CopernicaMarketingSoftware/AMQP-CPP.git /tmp/amqp-cpp
cd /tmp/amqp-cpp
mkdir -p build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release \
         -DAMQP-CPP_LINUX_TCP=ON \
         -DAMQP-CPP_BUILD_SHARED=OFF \
         -DCMAKE_INSTALL_PREFIX=/usr/local
cmake --build . -j"$(nproc)"
sudo cmake --install .
```

`-DAMQP-CPP_LINUX_TCP=ON` 开的就是 TCP 模块（`TcpConnection`/`TcpChannel`），不加它编译出来的库里连这两个符号都没有。`AMQP-CPP_BUILD_SHARED=OFF` 是为了链接进单二进制，省掉部署时的 `.so` 路径问题（`logs/`、`uploads/` 这类相对路径已经够我们操心的了）。

CMake 侧用最朴素的方式引入，不用 FetchContent——这个库的安装路径是固定的，没必要为了构建系统的优雅额外付出一份依赖管理复杂度：

```cmake
# CMakeLists.txt（本文新增片段）
find_path(AMQPCPP_INCLUDE_DIR NAMES amqpcpp.h PATHS /usr/local/include)
find_library(AMQPCPP_LIBRARY NAMES amqpcpp PATHS /usr/local/lib)
if(NOT AMQPCPP_INCLUDE_DIR OR NOT AMQPCPP_LIBRARY)
  message(FATAL_ERROR "找不到 AMQP-CPP：先跑 scripts/install-amqpcpp.sh（务必带 -DAMQP-CPP_LINUX_TCP=ON）")
endif()

target_include_directories(seckill-cpp PRIVATE
    ${AMQPCPP_INCLUDE_DIR}
    ${AMQPCPP_INCLUDE_DIR}/amqpcpp)   # linux_tcp.h 在这个子目录里

target_link_libraries(seckill-cpp PRIVATE
    ${AMQPCPP_LIBRARY}
    pthread
    dl)
```

`pthread` 和 `dl` 是 TCP 模块明确要求的（内部会起线程、可能 `dlopen`），漏了会在链接期报一堆莫名其妙的符号缺失。`src/CMakeLists.txt` 的源文件清单里加上 `mq/MqEventLoop.cc`、`mq/MqClient.cc`。

## 五、MqEventLoop：一个够用的单线程 epoll

一百来行，但每一行都有存在的理由。重点是它除了 epoll 还提供一个 **eventfd 唤醒通道**——这是跨线程投递的唯一入口：

```cpp
// src/mq/MqEventLoop.h（本文新增）
#pragma once
#include <atomic>
#include <deque>
#include <functional>
#include <memory>
#include <mutex>
#include <unordered_map>

namespace seckill {

// 单线程 epoll 循环 + eventfd 跨线程投递通道。
// 约定：只有一个线程可以调用 run()/watchFd()/setInterest()/unwatchFd()；
//       post() 可以任意线程调用。
class MqEventLoop {
public:
    using EventCb = std::function<void(int fd, uint32_t events)>;

    MqEventLoop();
    ~MqEventLoop();
    MqEventLoop(const MqEventLoop &) = delete;
    MqEventLoop &operator=(const MqEventLoop &) = delete;

    void run();                                 // 阻塞，直到 stop()
    void stop();                                // 线程安全
    void post(std::function<void()> task);      // 线程安全：投递到 loop 线程执行

    void watchFd(int fd, EventCb cb);           // 仅 loop 线程
    void setInterest(int fd, uint32_t events);  // 仅 loop 线程；0 表示都不关心
    void unwatchFd(int fd);                     // 仅 loop 线程
    bool hasFd(int fd) const;                   // 仅 loop 线程

private:
    struct Reg {
        int fd{-1};
        uint32_t mask{0};
        EventCb cb;
    };

    void drain();

    int epfd_{-1};
    int wakefd_{-1};                            // eventfd：跨线程唤醒
    std::atomic<bool> running_{false};
    std::unordered_map<int, std::unique_ptr<Reg>> regs_;
    std::mutex tasksMu_;
    std::deque<std::function<void()>> tasks_;
};

}  // namespace seckill
```

实现里三个必须写对的细节（`post` 的 swap、`run` 的超时、`setInterest` 的幂等）：

```cpp
// src/mq/MqEventLoop.cc（本文新增）
#include "mq/MqEventLoop.h"
#include <spdlog/spdlog.h>
#include <sys/epoll.h>
#include <sys/eventfd.h>
#include <unistd.h>
#include <cerrno>
#include <cstring>
#include <stdexcept>
#include <string>
#include <vector>

namespace seckill {
namespace {

[[noreturn]] void throwErrno(const char *what) {
    throw std::runtime_error(std::string(what) + ": " + std::strerror(errno));
}

}  // namespace

MqEventLoop::MqEventLoop() {
    epfd_ = ::epoll_create1(EPOLL_CLOEXEC);
    if (epfd_ < 0) throwErrno("epoll_create1");
    // EFD_NONBLOCK：drain() 里可以一直 read 到 EAGAIN，不会被卡住。
    wakefd_ = ::eventfd(0, EFD_NONBLOCK | EFD_CLOEXEC);
    if (wakefd_ < 0) throwErrno("eventfd");

    auto reg = std::make_unique<Reg>();
    reg->fd = wakefd_;
    reg->mask = EPOLLIN;
    reg->cb = [this](int, uint32_t) { drain(); };
    epoll_event ev{};
    ev.events = EPOLLIN;
    ev.data.ptr = reg.get();
    if (::epoll_ctl(epfd_, EPOLL_CTL_ADD, wakefd_, &ev) < 0) throwErrno("epoll_ctl wakefd");
    regs_.emplace(wakefd_, std::move(reg));
}

MqEventLoop::~MqEventLoop() {
    ::close(epfd_);
    ::close(wakefd_);
}

// 任意线程调用：入队 + 敲一次 eventfd。
void MqEventLoop::post(std::function<void()> task) {
    {
        std::lock_guard<std::mutex> lk(tasksMu_);
        tasks_.push_back(std::move(task));
    }
    uint64_t one = 1;
    // EAGAIN 可以忽略：说明已有未被消费的唤醒信号，任务已经被打包进这一轮 drain。
    ::write(wakefd_, &one, sizeof one);
}

void MqEventLoop::drain() {
    uint64_t ticks = 0;
    while (::read(wakefd_, &ticks, sizeof ticks) == static_cast<ssize_t>(sizeof ticks)) {
    }
    // 关键点：swap 出来再执行，持锁期间不跑用户回调。
    // 否则回调里再 post() 就会自锁（生产者在消费者线程里等锁）。
    std::deque<std::function<void()>> local;
    {
        std::lock_guard<std::mutex> lk(tasksMu_);
        local.swap(tasks_);
    }
    for (auto &t : local) {
        try {
            t();
        } catch (const std::exception &e) {
            spdlog::error("[mq-loop] task threw: {}", e.what());
        }
    }
}

void MqEventLoop::run() {
    running_.store(true);
    std::vector<epoll_event> events(64);
    while (running_.load()) {
        // 不能用 -1 超时：那样 stop() 之后 loop 会卡在 epoll_wait 里醒不过来。
        int n = ::epoll_wait(epfd_, events.data(), static_cast<int>(events.size()), 1000);
        for (int i = 0; i < n; ++i) {
            auto *reg = static_cast<Reg *>(events[i].data.ptr);
            reg->cb(reg->fd, events[i].events);
        }
    }
}

void MqEventLoop::stop() { running_.store(false); }

void MqEventLoop::watchFd(int fd, EventCb cb) {
    if (regs_.count(fd)) return;
    auto reg = std::make_unique<Reg>();
    reg->fd = fd;
    reg->cb = std::move(cb);
    epoll_event ev{};
    ev.events = reg->mask;   // 先以 0 注册，真正关心什么由随后的 setInterest 决定
    ev.data.ptr = reg.get();
    if (::epoll_ctl(epfd_, EPOLL_CTL_ADD, fd, &ev) < 0) throwErrno("epoll_ctl add");
    regs_.emplace(fd, std::move(reg));
}

void MqEventLoop::setInterest(int fd, uint32_t events) {
    auto it = regs_.find(fd);
    if (it == regs_.end()) return;
    if (it->second->mask == events) return;   // 幂等：避免无意义的 epoll_ctl 系统调用
    epoll_event ev{};
    ev.events = events | EPOLLRDHUP;
    ev.data.ptr = it->second.get();
    if (::epoll_ctl(epfd_, EPOLL_CTL_MOD, fd, &ev) < 0) throwErrno("epoll_ctl mod");
    it->second->mask = events | EPOLLRDHUP;
}

// AMQP 重连后 fd 会换：先从 epoll 摘掉旧的，再由 monitor() 用新 fd 重新注册。
void MqEventLoop::unwatchFd(int fd) {
    auto it = regs_.find(fd);
    if (it == regs_.end()) return;
    ::epoll_ctl(epfd_, EPOLL_CTL_DEL, fd, nullptr);
    regs_.erase(it);
}

bool MqEventLoop::hasFd(int fd) const { return regs_.count(fd) != 0; }

}  // namespace seckill
```

这段循环是整个阶段三的地基。它的三个性质会在后面反复救我们的命：**单线程**（所有回调天然串行，不需要给 AMQP 对象加锁）、**可跨线程投递**（HTTP 线程唯一的出口）、**fd 所有权清晰**（重连换 fd 时 `unwatchFd` + `watchFd` 重建即可）。

## 六、MqHandler：把 `monitor()` 翻译成 epoll 事件

Handler 的职责只有一件：把 AMQP-CPP 的请求（"帮我盯着这个 fd 的可读/可写"）翻译成两行 epoll 操作。

```cpp
// src/mq/MqHandler.h（本文新增）
#pragma once
#include <amqpcpp.h>
#include <amqpcpp/linux_tcp.h>
#include <spdlog/spdlog.h>
#include <sys/epoll.h>
#include <functional>
#include "mq/MqEventLoop.h"

namespace seckill {

class MqHandler : public AMQP::TcpHandler {
public:
    using ReadyCb = std::function<void(AMQP::TcpConnection *)>;
    explicit MqHandler(MqEventLoop &loop) : loop_(loop) {}
    void setReadyCb(ReadyCb cb) { readyCb_ = std::move(cb); }

    void onConnected(AMQP::TcpConnection *connection) override {
        spdlog::info("[mq] 连接建立完成，可以开 channel 了");
        if (readyCb_) readyCb_(connection);
    }

    void onError(AMQP::TcpConnection *, const char *message) override {
        // 注意：走到这里连接已经不可用了，必须在日志之后安排重连，不能继续 publish。
        spdlog::error("[mq] 连接错误：{}", message);
    }

    void onClosed(AMQP::TcpConnection *) override {
        spdlog::warn("[mq] 连接已关闭");
        loop_.stop();   // 冒烟演示：真实服务里这里应该是"重连"而不是"停工"
    }

    // 心跳协商：接受服务器建议值。返回 0 等于关闭心跳，
    // 那样 NAT / 网关会在静默几十分钟后悄悄掐掉连接，而我们毫无察觉。
    uint16_t onNegotiate(AMQP::TcpConnection *, uint16_t interval) override {
        spdlog::info("[mq] 心跳协商结果：{}s", interval);
        return interval;
    }

    // 库唯一要求你必须实现的成员：把 fd 挂进你的事件循环。
    void monitor(AMQP::TcpConnection *connection, int fd, int flags) override {
        if (!loop_.hasFd(fd)) {
            loop_.watchFd(fd, [connection](int callbackFd, uint32_t ev) {
                uint32_t active = 0;
                if (ev & (EPOLLIN | EPOLLHUP | EPOLLRDHUP | EPOLLERR)) active |= AMQP::readable;
                if (ev & (EPOLLOUT | EPOLLERR)) active |= AMQP::writable;
                // 把"哪个 fd 发生了什么"交回给库，剩下的它自己处理，包括真正的 send/recv。
                connection->process(callbackFd, active);
            });
        }
        uint32_t want = 0;
        if (flags & AMQP::readable) want |= EPOLLIN;
        if (flags & AMQP::writable) want |= EPOLLOUT;
        // flags 为 0 时 want 也为 0 —— 这一分支必须支持，否则会 level-trigger 空转。
        loop_.setInterest(fd, want);
    }

private:
    MqEventLoop &loop_;
    ReadyCb readyCb_;
};

}  // namespace seckill
```

## 七、MqClient：地址、生命周期，以及第一条发出去的消息

URI 里写 vhost 有个坑：默认 vhost `/` 在 URI 中要么不写要么写成 `%2F`，而我们要的 vhost 本身叫 `/seckill`，写成 `amqp://user:pass@host:5672/seckill` 解析出来是 `seckill` 而不是 `/seckill`。与其去猜各家的转义规则，**直接用显式构造函数**，四个参数（host / port / login / vhost）一一对应，没有任何歧义：

```cpp
// src/mq/MqClient.cc（本文新增，节选）
#include "mq/MqClient.h"

namespace seckill {
namespace {
constexpr const char *kExchange = "seckill.order.direct";
constexpr const char *kQueue    = "seckill.order.create";
constexpr const char *kRoute    = "seckill.order.create";
constexpr const char *kConsumer = "seckill-consumer-1";
}  // namespace

void MqClient::start(const std::string &host, uint16_t port,
                     const std::string &user, const std::string &pass,
                     const std::string &vhost) {
    thread_ = std::thread([this, host, port, user, pass, vhost] {
        handler_ = std::make_unique<MqHandler>(loop_);
        handler_->setReadyCb([this](AMQP::TcpConnection *) { declareTopology(); });

        // 这三个对象的生命周期完全归本线程：构造函数在这里，析构也在 join 之前。
        AMQP::Address addr(host, port, AMQP::Login(user, pass), vhost);
        connection_ = std::make_unique<AMQP::TcpConnection>(handler_.get(), addr);
        // TcpChannel 不必等连接握手完成：握手期间的指令会被排队，连通后自动补发。
        channel_    = std::make_unique<AMQP::TcpChannel>(connection_.get());

        loop_.run();   // 阻塞在这里，直到 stop()
    });
}

void MqClient::declareTopology() {
    channel_->declareExchange(kExchange, AMQP::direct | AMQP::durable)
        .onError([](const char *m) { spdlog::error("[mq] declareExchange 失败：{}", m); });

    channel_->declareQueue(kQueue, AMQP::durable)
        .onSuccess([](const std::string &name, uint32_t msgs, uint32_t consumers) {
            spdlog::info("[mq] queue 就绪 name={} 积压={} 消费者={}", name, msgs, consumers);
        })
        .onError([](const char *m) { spdlog::error("[mq] declareQueue 失败：{}", m); });

    channel_->bindQueue(kExchange, kQueue, kRoute)
        .onError([](const char *m) { spdlog::error("[mq] bindQueue 失败：{}", m); });
}

// HTTP 线程唯一允许调用的入口：只投递，不触碰任何 AMQP 对象。
void MqClient::publish(const std::string &body) {
    loop_.post([this, body] {
        channel_->publish(kExchange, kRoute, body);
    });
}

void MqClient::startConsume() {
    loop_.post([this] {
        channel_->consume(kQueue, kConsumer)
            .onReceived([this](const AMQP::Message &msg, uint64_t deliveryTag, bool redelivered) {
                std::string body(msg.body(), msg.bodySize());
                spdlog::info("[mq] 收到 tag={} redelivered={} body={}", deliveryTag, redelivered, body);
                // 还在 loop 线程里，直接 ack 是安全的。
                channel_->ack(deliveryTag);
            })
            .onSuccess([](const std::string &tag) {
                spdlog::info("[mq] 消费者启动 tag={}", tag);
            })
            .onError([](const char *m) { spdlog::error("[mq] consume 失败：{}", m); });
    });
}

void MqClient::stop() {
    loop_.stop();
    if (thread_.joinable()) thread_.join();
    // join 之后才析构 connection_ / channel_ / handler_：对象必须在创建它们的线程里销毁。
    channel_.reset();
    connection_.reset();
    handler_.reset();
}

}  // namespace seckill
```

注意 `publish()` 的形态：它**不发 AMQP 消息**，它发的是"请在 loop 线程里帮我发一次"这个意图。这条 lambda 边界就是整个并发模型的护栏——HTTP 线程手上有 `this`，但永远拿不到 `channel_`。

## 九、验证清单

跑通之后，按这个清单自检一遍：

| 检查项 | 期望结果 | 不对的话先看哪里 |
| --- | --- | --- |
| 编译能找到 `linux_tcp.h` | 无报错 | 库编译时是否漏了 `-DAMQP-CPP_LINUX_TCP=ON` |
| 链接期无符号缺失 | 无报错 | target_link 是否带了 `pthread` `dl` |
| vhost 传对 | 日志出现心跳协商 | vhost 名错了会直接 `ACCESS_REFUSED`（注意是 `/seckill` 不是 `seckill`） |
| declare 全部成功 | 三条 onError 都不触发 | `seckill` 用户对 `/seckill` 是否有 configure/write/read 权限 |
| publish 100 收 100 | 100 == 100 | 少收先看 routing key 是否和 6.1 的 definitions 一致 |
| 进程退出干净 | 无 core、无 `[error]` | 是否 join 之后才 reset 连接对象 |

## 十、小结

| 决策点 | 选择 | 放弃的代价 |
| --- | --- | --- |
| 客户端库 | AMQP-CPP（全异步、零 IO） | 自己写 Handler，前期成本高于同步库 |
| 事件循环 | 独立 MQ IO 线程 + 原生 epoll | 多一个线程一个 epoll，代码自行维护 |
| 跨线程投递 | `eventfd` + lambda 队列 | 相比直接调用多一次 syscall（约 1~2μs） |
| fd 管理 | 自己维护注册表，`flags=0` 必须处理 | 相比 libevent 封装多写 100 行 |
| 对象生命周期 | 创建与析构都在 loop 线程 | 停止流程必须先 stop 后 join 再 reset |

🐾 **本篇的三句话**：

1. **AMQP-CPP 卖的是协议不是网络**——拿到它的前提是先回答"谁驱动事件循环"，这个问题答错了后面全错。
2. **狗绳只有一根**：HTTP 线程对 MQ 的全部能力就是投递一个 lambda，任何绕过这根的"便捷调用"都是数据竞争。
3. **本篇跑通的是 plumbing，不是架构**——消息此刻可能丢、可能重复、投递模式也还没设成 persistent。削峰的骨架有了，可靠性要在 6.8/6.9 补上。
